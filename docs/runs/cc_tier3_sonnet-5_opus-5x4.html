## Review findings

Reviewed after each phase, before the next was spawned; main agent made no
edits at any point.

### Phase 1 — Home Page

No defects found. `app.py`, `templates/base.html`, `templates/home.html`,
`tests/test_app.py` all match the roadmap exactly: `/` route, jumbotron
with the literal tagline, Bootstrap 5 CDN links, python.org favicon,
navbar with the three required links, `{% block content %}`, and the
`uvicorn.run("app:app", reload=True)` `__main__` block.

### Phase 2 — Invoice Board + Detail Pages

No critical or spec-conformance defects.

- **Minor/style**: the status→badge-class mapping
  (`{"draft": "text-bg-secondary", "sent": "text-bg-warning", "paid":
  "text-bg-success"}`) is redefined identically as a `{% set %}` in both
  `templates/invoices.html:2` and `templates/invoice_detail.html:2`
  instead of being defined once (e.g. in `base.html`) and reused. The
  roadmap doesn't require centralization, so this is not a spec
  violation — logged as duplication only.
- Seed data (`models.py:31-105`) correctly satisfies every roadmap
  constraint: all three statuses present among the 5 invoices, 5
  payments spread across 3 invoices (2, 3, 4), invoice 3 (`paid`) has
  payments summing to exactly its amount, and no payments exist on
  either draft invoice (1, 5).
- `get_invoice`, `payments_for`, `paid_total`, `new_invoice_id` in
  `models.py:108-127` match the roadmap's signatures and rounding
  requirement.

### Phase 3 — Create Invoices, Record Payments, Lifecycle

No defects found.

- `app.py:68` — `GET /invoices/new` is declared before `GET
  /invoices/{invoice_id}` (`app.py:119`), correctly avoiding the
  int-path-converter shadowing footgun the spec plants.
- `parse_amount()` (`app.py:24-34`) uses `math.isfinite` and rejects
  `<= 0`, correctly catching `nan`/`inf`/`-inf` per the roadmap's
  explicit non-finite-amount requirement.
- 422 re-renders preserve raw submitted text (including unparsed
  amount strings) in both the new-invoice form and the payment form;
  400s use the exact `detail=` message templates the roadmap specifies
  for illegal transitions and premature `sent → paid` moves
  (`app.py:169-183`).
- Transition condition is `paid < invoice.amount` (i.e. redirect/allow
  only when `paid >= amount`), matching the roadmap's `paid_total(id)
  >= amount` gate.
- "New invoice" button present on the invoice board
  (`templates/invoices.html:14`).

### Phase 4 — Stats Page + JSON API

No defects found.

- `GET /stats` (`app.py:188-206`) computes all three status counts
  (zero counts included, since the dict comprehension iterates all of
  `STATUSES`) plus invoiced/collected/outstanding totals, each rounded
  to 2 decimals; `templates/stats.html` renders the exact required
  line text.
- `GET /api/invoices` (`app.py:209-222`) returns all 7 required fields
  per object, `created_at` via `.isoformat()`, sorted by `id` ascending.
