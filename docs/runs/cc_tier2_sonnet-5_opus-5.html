**Minor/style**

- `app.py:54-61` — amount parsing uses bare `float(amount)` with only a
  `<= 0` check. `float("nan")` succeeds and `nan <= 0` evaluates `False`,
  so a `POST` with `amount=nan` slips past validation and creates an
  expense with a `NaN` amount instead of being rejected as required
  ("amount must ... be strictly greater than 0"). Similarly
  `float("inf")` is accepted as a valid positive amount. Neither the
  roadmap's own test list nor the held-out acceptance suite exercises
  these inputs, so it does not fail verification, but it is a real gap
  against the "reject non-numeric text" requirement's intent (`nan`/`inf`
  are not usable numeric amounts). A `math.isfinite()` check would close
  it.
- `templates/expenses.html:31-32` and `templates/expense_detail.html:15-16`
  — the category badge link interpolates `expense.category` directly into
  the query string (`/expenses?category={{ expense.category }}`) without
  URL-encoding. Jinja2's autoescaping covers HTML entities but not URL
  encoding, so a category containing `&`, `#`, or a space would produce a
  broken link. Harmless with the current seed data (single-word lowercase
  categories) and not exercised by any test, but worth flagging as a
  latent bug if categories ever contain spaces or symbols.

No other issues found. No extraneous files, dependencies, or features were
