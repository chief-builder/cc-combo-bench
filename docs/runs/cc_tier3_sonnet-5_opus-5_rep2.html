## Review findings

Reviewed `app.py`, `models.py`, all five templates (`base.html`, `home.html`,
`invoices.html`, `invoice_detail.html`, `invoice_new.html`, `stats.html`), and
`tests/test_app.py` against `specs/tier3-invoicedesk/roadmap.md` phase by phase.

**Critical/functional:** none found.

**Spec-conformance:** none found.

**Minor/style:**
- `app.py:22-30` (`parse_amount`) — `float(raw)` accepts the strings `"nan"`
  and `"inf"`/`"-inf"` without raising `ValueError`, and the guard
  `if value <= 0: return None` does not catch them (`nan <= 0` and
  `inf <= 0` are both `False` in Python). A client posting
  `amount=nan` (invoice create or payment record) would pass validation and
  create an `Invoice`/`Payment` with a non-finite amount, corrupting later
  `%.2f` formatting, `paid_total` sums, and the `sent -> paid` money-gate
  comparison. The roadmap's literal test list never exercises this, so it
  does not fail any scripted check, but it is a real gap versus "amount must
  parse as a number and be strictly greater than 0."

Notes on things specifically checked and found conformant:
- `Invoice`/`Payment` dataclass field order and defaults match the roadmap;
  `created_at`/`paid_at` use `field(default_factory=lambda: datetime.now(timezone.utc))`,
  which is the correct way to get a per-instance "evaluated at construction time"
  default (a bare `datetime.now(timezone.utc)` default would be evaluated once at
  import time and shared by every instance).
- `STATUSES` and `ALLOWED_TRANSITIONS` module constants match verbatim.
- Seed data: 5 invoices (id 1-5) covering all three statuses (2 paid, 2 sent,
  1 draft); 6 payments across invoices 1, 2, 4, 5. Every paid seed invoice's
  payments sum to at least its amount (invoice 1: 1250.00 == 1250.00; invoice 4:
  940.25 == 940.25). Payments exist only on sent/paid invoices (none on draft
  invoice 3).
- `GET /invoices/new` (app.py:69) is registered before `GET /invoices/{invoice_id}`
  (app.py:123), so `/invoices/new` is not swallowed by the int path parameter.
- Status-filter validation (app.py:50-66), 404 on unknown invoice (app.py:123-130),
  payment-status gate returning the exact `Cannot record a payment on a {status}
  invoice` detail message (app.py:143-147), lifecycle transition and money-gate
  checks with the exact `Cannot move invoice from {x} to {y}` and `Cannot mark
  invoice paid: $P.PP of $A.AA paid` detail messages (app.py:173-186), and the
  `/api/invoices` route sorted by id ascending with all seven required fields
  (app.py:212-225) all match the roadmap literally.
- 422 re-renders preserve raw submitted text for both the invoice-create form
  (`invoice_new.html`) and the payment form (`invoice_detail.html`), including
  non-numeric amount text.
- Amounts are rendered via `"%.2f"|format(...)` (no thousands separator) in every
  template, consistent with the roadmap's literal `$X.XX` format.
- No dependencies added; `requirements.txt`/`requirements.lock` unchanged from
  the stripped worktree baseline (`fastapi[standard]==0.115.10`, `pytest==8.3.4`).
- The worktree's missing `PLAN.md`/`acceptance/`/`prompts/`/`results/`/`scripts/`
  directories are expected: `scripts/new_worktree.sh` deliberately strips them
  when the worktree is created, not something the sub-agent deleted.
